# 执行协议 · 全局（execution/00-protocol）

> 本文是 **AI 执行者的作业契约**：规定「按什么动作序列干活、何时必须停下来问、什么算完工」。
> 分工：`architecture/*`＝契约（做什么）、`DEVELOPMENT_GUIDE`＝工程规范（怎么写）、`30-guardrails`＝阈值权威、**本文＝执行行为**。
> 适用于 `blueprint-runtime/` 下全部源码工作。后端/前端差异见 [`10-backend.md`](./10-backend.md) / [`20-frontend.md`](./20-frontend.md)——它们只写**增量**，本文是共享真相，不在那里复制。

---

## 1. 为什么需要它

规范再完备，也挡不住执行者在「规范沉默处」即兴发挥。本文把执行变成闭环：

```text
规范(单一合法解) ─► 写测试 ─► 实现到绿 ─► 护栏验收 ─► 完工
      ▲                                          │
      └─────── 规范沉默 / 有歧义：停下来问 ◄──────┘
```

保证的不是「零偏离」，而是偏离必然**被堵死 / 被抓住 / 被叫停**三者之一。

---

## 2. 单任务循环（死板照做）

一个「任务」＝ 建造序里的**一个文件**（含其测试）。每个任务严格走六步：

```text
0 选任务   按当前阶段建造序（后端 10 §11 / 前端 20）取下一个未完成文件，不跳号
1 读规范   读该文件对应的 architecture 节 + testing 清单里它的条目
2 先写测试 把 testing 清单列的具名用例写成失败测试（red）——一个用例一个 it()
3 实现到绿 最小实现让测试 + 护栏通过；不写超出该文件单一职责的任何东西
4 自检     pnpm check（lint + test + 镜像）全绿
5 收口     勾 PROGRESS；按 GUIDE §9 一个文件一个提交
```

> 顺序不可调换：**测试先于实现**。先有规范定义的红灯，才有「实现 == 规范」的证据。

---

## 3. 停-问规则（拱顶石）

遇到以下任一情形，**立即停，不要写代码**，向人陈述「卡点 + 2–3 个候选 + 我的倾向」，等裁定：

- 规范对当前文件的某行为**没写**，或**两处可不同解读**；
- 需要新增/修改**任何契约面**：事件类型名、拒绝码、`ERR.*` 码、端口/lane、payloadType、接缝接口签名、目录结构、阶段顺序；
- 需要**新增依赖**或**调阈值**；
- `testing` 清单与 `architecture` 冲突，或某用例**不改契约就过不了**。

**禁止**：臆造默认值、顺手改契约凑测试、为了变绿放宽断言/删用例、把「待问」偷偷实现成某个猜测。

---

## 4. 完工闸门

一个任务**只有全部满足才算完工**，否则不得声称完成：

- 护栏 `pnpm check` 全绿；
- `testing` 清单该模块的**每个具名用例**都存在且绿（不是「测了几个」）；
- 没有新增 `eslint-disable`（如确需，已带理由并在评审登记）；
- 改动**属于当前阶段**，无越界。

> 「我觉得差不多了」不是完工。完工是机器判定，不是自我感觉。

---

## 5. 不越界

- 只碰**当前阶段建造序**里的文件；地基阶段（F-guard、F0–F6）**禁写任何功能（节点业务）代码**；
- 不顺手重构相邻文件、不加「以后可能用得上」的抽象；
- 范围之外发现的问题 → 记进 PROGRESS「待办/疑点」，不就地动手。

---

## 6. 阶段门（DAG，非直线）

阶段是依赖图（DAG，见 GUIDE §10），不是直线：

- 某阶段验收**不全绿，不许碰它的下游**阶段；
- **无依赖关系的两支可并行**（runtime F1–F3 ∥ editor F4–F6）；跨支硬墙只有上游的 **F0 + 契约冻结点** 与下游的 **Fx 集成**；
- editor 支在 Fx 之前一律对 **mock adapter + 冻结契约** 编码，不等 runtime 真实现。

---

## 6.1 阶段交接播报（完成一个阶段后必做）

一个阶段验收全绿、收口之后，**主动产出一段「阶段交接」再停下**，至少含：

- **已完成**：本阶段交付物 + 验收状态（哪些 manifest / 冒烟绿了）；
- **下一步内容**：按 DAG **解锁了哪个/哪些阶段**（含可并行的支）+ 各自要做什么；
- **方向与风险**：下阶段关键设计点、待确认项、本阶段遗留的停-问；
- **给协作方的接口**：若解锁了并行支，点明对方该照哪份**冻结契约**编码。

> 目的：让人（或接手的 agent）**无需追问**就知道「现在在哪、接下来往哪走」。这是主动告知，不是等人问。

---

## 7. 决策权清单

| 可自决（纯实现内部，放手） | 必须停-问（任何契约面） |
| --- | --- |
| 私有/辅助函数怎么拆 | 新增或改 事件类型 / 拒绝码 / `ERR.*` |
| 局部变量命名、注释措辞 | 新增或改 端口 / lane / payloadType |
| 用哪个标准库 API | 改 接缝接口签名（10 §10 / 20） |
| 测试内部如何组织（只要覆盖清单用例） | 新增依赖 / 调阈值 / 改目录结构 |
| 文件内实现细节 | 跨层 import / 改阶段顺序 / 动 `core/` 契约 |

> 一句话判据：**改了别处文件能观察到的「形状 / 词表 / 规则」→ 必须问；只改本文件内部怎么实现 → 自决。**

---

## 8. 与其他文档的优先级

- 契约面冲突（数据形状 / 事件 / 码 / 阈值）：以 `architecture/*`、`30-guardrails` 为准；
- 执行行为冲突（怎么做、何时停）：以本文为准；
- 人在本次会话里的临时指令可覆盖本文，但**覆盖即需把对应文档改掉**（否则下次又漂）。
