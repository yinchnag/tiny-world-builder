# Contex MCP Evidence and Reconstruction Boundaries

## Confidence vocabulary

- **Confirmed** — directly present in a committed file or recovered Git object.
- **Strong inference** — supported by multiple independent traces.
- **Proposed** — required for a practical rebuild but not recoverable from the
  available evidence.

## Primary evidence

### Current client configuration

`.codex/config.toml` and `.mcp.json` configure an HTTP MCP server named
`contex`. Historical ports include:

- `127.0.0.1:52224/mcp`
- `127.0.0.1:53961/mcp`
- `127.0.0.1:54620/mcp`
- `127.0.0.1:62440/mcp`

Later configurations include an Authorization bearer token. This indicates:

1. the server was dynamically started on a local port;
2. clients connected over MCP HTTP rather than stdio;
3. authentication was added or enabled later;
4. project files were client configuration, not server source.

Confidence: **Confirmed**.

### Contex-managed agent protocol

`.claude/CLAUDE.md` identifies the environment as:

> CodeSurf, an infinite canvas workspace where multiple AI agents collaborate.

It exposes the tile identifier through `CARD_ID` and requires every terminal
agent to call:

```text
peer_set_state(tile_id=$CARD_ID, tile_type="terminal", status="idle", task="Ready")
peer_get_state(tile_id=$CARD_ID)
```

The documented tools are:

- `peer_set_state`
- `peer_get_state`
- `peer_send_message`
- `peer_read_messages`
- `peer_add_todo`
- `peer_complete_todo`
- `canvas_create_tile`
- `terminal_send_input`
- `chat_send_message`

The protocol also requires agents to publish files being edited and coordinate
before touching a file claimed by a linked peer.

Confidence: **Confirmed**.

### Recovered first-generation tile files

Git objects contain:

```text
.contex/tile-1779176041759/
  objective.md
  skills.json
  state.json
  peers.md

.contex/tile-1779624672511/
  peers.md
```

`objective.md` contains:

- discovered local Skills and Commands;
- a tile-specific MCP communication protocol;
- a tile channel such as `tile:tile-1779176041759`;
- rules to reload the objective, update tasks, and notify a human.

The first-generation tools listed there are:

- `update_task(channel, task_id, status)`
- `create_task(channel, title)`
- `reload_objective(tile_id)`
- `pause_task(channel, task_id, reason)`
- `get_context(tile_id)`
- `notify(channel, message)`

`state.json` contains:

```json
{
  "tasks": [],
  "paused": false
}
```

`peers.md` is auto-updated when canvas links change and identifies:

- peer tile ID;
- peer tile type;
- valid tools for communicating with that peer.

Confidence: **Confirmed**.

### Recovered second-generation tile files

Commit `e8ecefb` on June 8, 2026 added:

```text
.contex/tile-1780832070725/
  objective.md
  skills.json
  state.json
```

The tile enabled the repository-local TinyWorld i18n Skill plus standard
commands. Commit `ea60b20` on June 9 removed these files and added `.contex` to
ignore rules.

Strong interpretation:

- early versions materialized tile state inside the repository;
- later versions moved runtime state outside Git or into the MCP server;
- generated tile files were considered ephemeral after the protocol matured.

Confidence: **Strong inference**.

### Peer graph behavior

Recovered `peers.md` files show a terminal/chat pair linked on the canvas.
Changing links caused generated peer files to change. The text explicitly calls
links “canvas links.”

This proves the canvas edge graph was operational data, not only visual layout.
Links determined communication capabilities and peer discovery.

Confidence: **Confirmed**.

### Workspace memory

Historical `.codesurf/DREAMING.md` files are labelled:

- “CodeSurf Workspace Memory”
- “Generated by dreaming daemon”
- “Do not hand-edit”

They consolidate architecture, recent work, constraints, open threads, module
maps, deployment risks, and durable decisions over many sessions.

Contex likely supplied access and reload plumbing, while CodeSurf or a
separate daemon produced the summaries.

Confidence:

- memory file and daemon behavior: **Confirmed**;
- exact ownership by Contex versus CodeSurf: **Unknown**.

## Reconstructed protocol generations

### Generation 1: channel/task oriented

Primary abstractions:

- tile channel;
- objective files;
- task list;
- paused state;
- context retrieval;
- generic notifications.

### Generation 2: peer oriented

Primary abstractions:

- current tile state;
- linked peer discovery;
- file claims;
- direct inbox;
- shared todos;
- direct tile-type actions.

The rebuild should support both generations through aliases over one internal
model.

## Git-history observations

- `.mcp.json` was repeatedly updated from June 3 through June 23, 2026.
- `.contex` tile data existed in multiple branches and commits before being
  removed from tracked source.
- commits and branches show heavy concurrent agent activity.
- worktree audits mention `.claude/.../agent-*`, `.codex/worktrees`, and many
  independent feature branches.
- PollyArranger explicitly describes Contex as the peer-messaging MCP server
  agents used to coordinate on CodeSurf Canvas.

These establish real operational use, not merely planned integration.

## What cannot be recovered exactly

- original server language and framework;
- complete MCP tool list and exact JSON Schemas;
- persistence technology;
- event delivery implementation;
- canvas graph storage format;
- authentication lifecycle;
- multi-user tenancy model;
- message retention;
- presence timeout values;
- server discovery/startup process;
- whether tasks were globally ordered or channel-scoped;
- extension bridge internals.

The development plan therefore targets behavioral compatibility rather than
source compatibility.

## Security note

Historical tracked files contain local bearer tokens. A rebuild must never store
live tokens in version-controlled project files. Use:

- ephemeral session tokens;
- OS keychain or environment variables;
- loopback-only binding by default;
- explicit remote-access configuration;
- token rotation and expiry.
