# CodeSurf Evidence and Reconstruction Boundaries

## Confirmed evidence

### Infinite canvas and multiple AI agents

The contex-managed Claude instructions explicitly state that the agent runs
inside an “infinite canvas workspace where multiple AI agents collaborate.”

### Tile/block identity

Each agent receives a block identifier through `CARD_ID`. Historical data uses
IDs such as:

```text
tile-1779176041759
tile-1779624672511
tile-1780832070725
```

The terms tile, block, and card appear to refer to the same primary canvas
object at different integration layers.

### Tile types

Confirmed types:

- terminal;
- chat.

Tools and historical Skill descriptions strongly imply:

- extension/custom tile;
- possibly browser and document-like tiles.

Only terminal and chat should be labelled historical facts.

### Canvas links

Recovered `peers.md` files state that linked blocks are peers and are
auto-updated when canvas links change. This proves:

- tiles can be connected visually;
- links alter peer discovery;
- links control available communication actions.

### Tile-local objective and Skills

Historical `.contex/tile-*` directories contain:

- objective;
- enabled Skills/Commands;
- task state;
- peer links.

One tile exposed a very large discovered user Skill library; another exposed
only the repository-local TinyWorld i18n Skill. This demonstrates per-tile Skill
configuration.

### Terminal and chat control

The protocol exposes:

- sending terminal input;
- sending messages to chat tiles;
- acknowledging chat requests;
- creating tiles from an agent.

Therefore CodeSurf was not merely a diagram: tiles had live, controllable
behavior.

### Workspace Memory

`.codesurf/DREAMING.md` persisted for more than a month and was repeatedly
updated. Later versions say:

> Generated by dreaming daemon. Do not hand-edit.

The memory includes:

- architecture;
- durable coding rules;
- module maps;
- recent features;
- open threads;
- deployment facts;
- mistakes and traps;
- local-only work not yet pushed.

### Development side effects

Historical memory states that CodeSurf could auto-commit and auto-push main,
causing Netlify production deployment. This is a confirmed behavior of the
historical environment, but it should not be the safe default of a rebuild.

### Workflow runtime

`.claude/workflows/split-god-file.js` uses host-provided primitives:

- `phase(...)`;
- `parallel(...)`;
- `agent(...)`;
- `log(...)`.

The workflow:

1. launched eight analysis agents in parallel;
2. launched a planning agent with structured schema output;
3. launched an execution agent;
4. launched a verification agent using Playwright MCP;
5. returned a structured workflow result.

This implies CodeSurf or its surrounding runtime supported programmable
multi-agent workflows, phase reporting, parallel execution, and structured
results.

## Strong inferences

### Canvas as operational dashboard

Because tile states, tasks, messages, links, terminal input, and notifications
are available, the canvas likely displayed:

- current status;
- task name;
- agent identity/model;
- attention state;
- output/terminal stream;
- link topology.

### Local process supervision

Terminal tiles must have launched or attached to real local processes. Exact PTY
implementation is unknown.

### Extension system

A discovered historical Skill describes CodeSurf extensions using:

- `extension.json`;
- optional Node.js backend;
- HTML tile UI;
- `main.js` with `activate()`;
- `window.contex` bridge.

This is indirect but detailed evidence. Treat it as a likely extension contract,
not a recovered authoritative implementation.

### Dreaming daemon event input

Workspace Memory changed alongside project work. It likely consumed:

- Git history;
- repository state;
- tile summaries;
- agent conversation/session outputs;
- explicit user memory.

The exact prompt and update policy are unknown.

## Unknown internals

- UI framework;
- canvas rendering library;
- layout document format;
- PTY library;
- process sandbox;
- tile resize/minimize behavior;
- exact extension API;
- whether workflows were first-class canvas tiles;
- how agent model/auth settings were stored;
- how automatic Git actions were configured;
- memory summarization model and prompt.

## Reconstruction standard

The rebuild should preserve:

- tile-based infinite canvas;
- meaningful links;
- live terminal/chat interaction;
- Contex MCP integration;
- per-tile objective and Skills;
- status and conflict visibility;
- long-term workspace memory;
- programmable workflows.

It should deliberately change unsafe historical defaults such as automatic
push-to-main.
