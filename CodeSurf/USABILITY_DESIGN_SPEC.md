# CodeSurf 网页可操作性设计规范

> 适用范围：CodeSurf 浏览器画布、Electron 桌面壳中的同一 Web UI，以及后续新增的工作区、Tile、Contex 协作和终端操作界面。

## 1. 目标与原则

CodeSurf 是面向人和 agent 共同工作的画布。界面设计的首要目标不是展示功能数量，而是让首次使用者能在不阅读源码的前提下完成：创建工作区、理解画布、创建 Tile、连接 Tile、运行任务并知道系统当前状态。

### 1.1 可操作性原则

1. **每次操作都必须有结果。** 点击后必须出现成功、处理中或失败三者之一；不得静默失败。
2. **先让用户开始，再逐步暴露复杂度。** 首次进入只需要完成工作区创建；Contex、终端、agent 和连线属于渐进披露能力。
3. **状态必须可见且可解释。** 禁用、离线、保存、执行、失败和阻塞状态都应有文字、颜色与下一步建议，不能只依赖颜色。
4. **危险动作可撤销或可确认。** 删除 Tile、停止终端、取消任务等应提供撤销、确认或恢复入口。
5. **平台感知。** 文件路径示例、快捷键文案和窗口行为应符合当前操作系统；不能把 Windows 示例硬编码给 macOS/Linux 用户。
6. **键盘与鼠标同等可用。** 关键流程必须能用键盘完成；画布的鼠标手势必须有可发现的替代入口。
7. **离线降级清楚。** Contex 未连接时，画布基本功能仍可用；只有依赖 Contex 的动作才提示连接要求与启动方式。

## 2. 信息架构与层级

顶部工具栏按意图分组，组间通过间距和轻量分隔区分：

| 分组 | 内容 | 要求 |
| --- | --- | --- |
| 工作区 | 工作区切换器、新建、当前仓库信息 | 始终在左侧；新建是明确主动作。 |
| 创建 | Tile 类型选择器、添加 Tile | 添加动作的名称和类型选择保持相邻。 |
| 视图 | 适配画布、缩放百分比、重置缩放、帮助 | 用可见文案而非仅图标或数字。 |
| 协作 | Contex 状态、终端/agent 摘要 | 明确在线、连接中、离线、错误，以及各状态影响。 |
| 保存 | 保存中、已保存、恢复提示 | 放右侧并保留足够宽度，不截断关键信息。 |

工具栏不能把需要解释的状态藏进 tooltip。`title` 只能补充信息，不是唯一说明方式。

## 3. 工作区创建规范

### 3.1 表单字段

| 字段 | 规则 | 反馈 |
| --- | --- | --- |
| 名称 | 必填，去除首尾空白，建议 2–80 字符 | 空值时就地提示“请输入工作区名称”。 |
| Repository path | 必填，必须为本机存在的目录 | 输入框下方常驻帮助文字，提交时校验目录存在。 |

路径输入必须：

- 按平台显示示例：macOS/Linux 为 `/Users/name/project/repo`，Windows 为 `C:\\Users\\name\\project\\repo`。
- 提供“选择文件夹”能力；浏览器安全限制不支持时，清楚说明只能粘贴绝对路径。
- 不要求目录必须是 Git 仓库，除非后续功能确实依赖 Git；若检测到不是 Git 仓库，可给非阻塞提示。
- 允许用户从最近仓库中快速选择，但不自动读取或发送仓库内容。

### 3.2 提交流程

1. 用户点击 Create 或按 Enter。
2. 前端立即校验空值与明显格式问题。
3. 提交期间按钮禁用，文案变为“Creating…”，并保留 Cancel。
4. 成功后关闭弹窗，切换到新工作区，展示欢迎卡片。
5. 失败后弹窗保持打开，保留输入内容，在字段附近显示具体错误，并把焦点置于可修正字段。

禁止：先关闭弹窗再异步创建；失败时清空错误信息；用“发生错误”替代具体可行动的说明。

## 4. 空状态与首次使用引导

当没有工作区时，应展示专门的空状态页或模态引导，而不是只有一个常规表单：

- 标题：`创建第一个工作区`。
- 说明：`工作区将保存画布布局；仓库仍保留在本机。`
- 主操作：`选择仓库文件夹` / `创建工作区`。
- 辅助操作：`查看示例工作流`。

当工作区为空时，在画布中央显示可关闭的欢迎卡片：

1. 添加一个 Tile；
2. 拖动 Tile 标题栏移动；
3. 从输出端口拖到另一个 Tile 建立连接；
4. 可选：连接 Contex 后启用协作消息、命令和 agent 状态。

欢迎卡片不应阻塞双击画布等基本操作，并应记录“已关闭”状态。

## 5. 画布交互规范

### 5.1 基础动作

| 动作 | 鼠标入口 | 键盘/菜单替代 | 可见反馈 |
| --- | --- | --- | --- |
| 新建 Tile | 工具栏、双击空白画布 | `N` 或命令面板 | Tile 出现动画并获得焦点。 |
| 选择 Tile | 单击 Tile | Tab 焦点导航 | 高亮边框与状态栏说明。 |
| 移动 Tile | 拖标题栏 | 方向键微调（可选） | 拖动预览、释放后保存状态。 |
| 建立连线 | 拖输出端口至目标 | Tile 菜单“连接到…” | 临时连线、合法目标高亮、完成提示。 |
| 删除 Tile | Tile 的删除按钮 | Delete/Backspace + 确认或撤销 | toast 提供 Undo。 |
| 视图导航 | 空白处拖拽、滚轮缩放、minimap | Fit、重置、快捷键 | 常驻缩放值与简短提示。 |

### 5.2 防错与恢复

- 任何删除操作至少提供 5 秒 Undo；若无法撤销，必须二次确认。
- 保存失败不能只改变颜色，必须显示“重试”和失败原因。
- 连线失败要说明原因，例如“不能连接到自身”“目标 Tile 已删除”或“Contex 未连接，但本地连线已保存”。
- 切换工作区前若仍在保存，显示非阻塞进度；失败时不得静默丢弃布局。

## 6. Contex 与终端的状态设计

Contex 状态必须分成以下可见状态：

| 状态 | 文案 | 用户影响 | 建议操作 |
| --- | --- | --- | --- |
| connected | `Contex 已连接` | 协作、命令与聊天可用 | 可查看详情。 |
| connecting | `正在连接 Contex` | 协作能力暂不可用 | 等待或查看日志。 |
| disconnected | `Contex 未启动` | 本地画布正常；协作能力不可用 | 提供“启动方式”说明。 |
| error | `Contex 连接失败` | 协作能力不可用 | 展示可复制错误与重试。 |

终端 Tile 需同时展示进程状态（未启动、运行中、已退出、失败）、最近退出码和可执行动作（启动、停止、重试、查看完整输出）。不能让用户通过空白输出猜测进程是否已运行。

## 7. 可访问性与响应式要求

- 所有输入框必须关联可见 `<label>`；所有图标按钮必须有可访问名称。
- 焦点样式必须明显，不能只靠 hover；对话框打开时焦点进入第一个字段，关闭后回到触发按钮。
- 颜色不是唯一状态表达方式，状态点需配文字或 aria-label。
- 支持键盘创建、选择、删除、关闭对话框和恢复缩放。
- 1280px 以下工具栏可换行或折叠为“更多”；minimap 可缩小或隐藏，不能遮挡主要编辑区域。
- 最低目标为 WCAG 2.2 AA 的文本对比度、焦点可见性和键盘可达性。

## 8. 验收标准

每次影响网页交互的改动至少满足：

1. 新用户可在 60 秒内完成工作区创建，且失败时能看懂并修正错误。
2. 创建、保存、运行、停止、连接、删除六类操作均有成功/处理中/失败反馈。
3. 无 Contex 时，创建工作区、添加 Tile、移动、连线、保存和重新打开仍可用。
4. 画布核心流程可只用键盘完成基本操作，且无键盘焦点陷阱。
5. 常见窗口宽度下，工具栏和 minimap 不遮挡主要动作。
6. 新增交互应补充自动化测试；复杂手势补充浏览器冒烟测试与人工验收记录。
